# Live Output workspace

Output is a separate Build tab. Design history and its approval gates stay intact. The orchestrator assigns one UI task ownership of `.helix/output/**` in the reviewed plan; other workers coordinate through that owner. That worker (or a direct UI task) builds the actual application source and copies its self-contained compiled browser bundle into a committed `.helix/output/index.html` export, with relative asset URLs, while implementation continues. For plain HTML/CSS/JS applications these are the actual source assets. A separate imitation or mocked interface is not Output evidence. Core refreshes a task-owned loopback listener after meaningful worker turns. No project script/configuration is executed by the preview host. Backend-dependent applications and arbitrary development commands are not supported by this provider. A server execution provider needs a separately reviewed boundary; no new infrastructure is assumed.

The event `output.updated` records worker/root Build identity, revision, branch, exact commit, SHA-256 artifact digest, approved-brief/original-goal digest, complete design-state digest, lifecycle and feedback. Digests bind context; they are not acceptance verdicts. Brief/design content remains in its existing session/design events, including future palette fields. Approval changes invalidate feedback until a fresh preview binds that context. `.helix/output` is read from Git blobs at the recorded commit, never from mutable working files. The export must actually be included in the commit; ignored or absent output fails visibly. No process IDs, ports, file contents or URLs are persisted in events.

`GET /api/sessions/:id/output/lease` returns a private live-only lease (revision, digest, URL, stale and pending-edit flags) only while this daemon owns the listener. Replay consumes event projections and never requests leases, mounts preview frames or starts servers. Reconnect revalidates ownership. Restart records running/starting previews as stopped and does not recover listeners by PID/port. Start, Stop, feedback and human disposition use revision-bound `POST /api/sessions/:id/output` commands with request receipts. Original Build/goal, ReviewedBrief, plan review, design, CI and merge gates remain unchanged.

Preview hosting is bounded to three simultaneous preparations/listeners, 500 regular files, 32 MiB per export, 30 seconds startup and 30 minutes lifetime. The OS atomically assigns a free loopback port. Only the in-memory committed file map is served. Symlinks/submodules, dotfiles, unknown file types, arbitrary paths, commands, ports and URLs are refused. Only owned listeners are closed; no process-tree or port-based kills occur. Explicit stop prevents automatic restart at subsequent turns until Start is chosen again.

The browser uses an opaque `sandbox="allow-scripts allow-forms"` frame on a separate owned origin, a trusted wrapper constraining child navigation to the artifact capability, and supported restrictive CSP. Client-side submit handlers can process forms; enforced `form-action 'none'` blocks native form submission in both documents. Top navigation, popups, workers, cookies and persistent storage are not enabled. Helix rejects preview/null origins for privileged APIs and refuses iframe navigation into its UI/API. No privileged message bridge or arbitrary filesystem route is exposed. Per-wrapper launch tickets are single-use and capabilities are bounded. Only the trusted wrapper sends viewer-readiness messages; application messages cannot approve or route changes.

This is ordinary browser origin/sandbox isolation, not complete network confinement. In particular, `connect-src 'none'` is not a guarantee of WebRTC blocking. Output does not depend on the unsupported `webrtc` CSP directive or a speculative violation-event capability probe. No browser permissions or security settings are changed. Real interaction and hostile navigation/resource tests are required for acceptance; frame load alone is not success. See [HTML sandbox](https://html.spec.whatwg.org/multipage/iframe-embed-object.html#attr-iframe-sandbox) and [CSP frame navigation](https://www.w3.org/TR/CSP3/#directive-frame-src).

Initial-load reliability remains an open limitation: browser validation observed a blank first navigation even after the automatic retry. The viewer retries once after 10 seconds without readiness, then reports unavailable after another 10 seconds. Manual Reset clears the failure and starts another bounded attempt; it successfully loaded the tested application. This recovery is not evidence that initial loading is reliable.

Feedback attaches to the exact revision/commit and is rejected when that commit, approved context or working checkout changed. It is queued as one bounded instruction to the owning worker, which must request new approval for scope/design changes. History distinguishes queued/routed, blocked and user-marked addressed/dismissed states; neither a completed turn nor a later preview silently means feedback succeeded. A durable pre-send attempt marker suppresses uncertain duplicate delivery. After daemon restart unresolved Output feedback is marked blocked for inspection; generic chat recovery does not resend Output instructions. This sacrifices automatic redelivery in a crash window to avoid silently duplicating changes. Existing ordinary chat semantics are unchanged.

Acceptance-verifier seam: consume `Output` plus the root session's ReviewedBrief, current design state and a current live lease with matching artifact hash/revision and `stale=false`, `pendingChanges=false`. Then perform real browser/application checks. Server readiness, iframe load, a static concept, CI or a resolved feedback marker alone never certifies acceptance. Synthetic fixtures test plumbing only.
